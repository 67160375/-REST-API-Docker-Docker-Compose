# User Journey: ระบบจองตั๋วชมการแข่งขันรถ

ที่มา: ไฟล์ User Journey Table / Comparison Chart ที่ทำไว้ (PDF ต้นฉบับ)

## ขั้นตอน (Step-by-step)

| ขั้นตอน | หน้าจอ / Touchpoint | การกระทำของผู้ใช้ | การตอบสนองของระบบ |
| --- | --- | --- | --- |
| 1. ค้นหารายการแข่ง | หน้าแรก (`/races`) | ค้นหา/เลือกดูรายการแข่งรถที่สนใจ (เช่น Thailand Super Series, BRIC Superbike) | แสดงการ์ดรายการแข่งขัน วันที่จัด สถานที่สนาม และราคาเริ่มต้น |
| 2. ดูรายละเอียด & รอบแข่ง | หน้ารายละเอียด (`/race-detail`) | กดดูรายละเอียดการแข่งขัน ตารางเวลา และผังสนาม (Venue Map) | แสดงรายละเอียด กิจกรรมในงาน (เช่น Pit Walk) และปุ่ม "เลือกโซนที่นั่ง" |
| 3. เลือกโซน & จำนวนตั๋ว | หน้าเลือกโซน (`/select-zone`) | เลือกโซนที่ต้องการ (Grandstand / Side Stand / VIP) และระบุจำนวนตั๋ว | แสดงผังโซน ตั๋วคงเหลือ real-time คำนวณราคารวม และล็อกตั๋วชั่วคราว |
| 4. กรอกข้อมูลผู้เข้าชม | หน้ากรอกข้อมูล (`/checkout`) | กรอกชื่อ-เบอร์โทรผู้ซื้อ และเลือกช่องทางชำระเงิน (พร้อมเพย์/บัตร) | Validate ข้อมูลความถูกต้อง real-time และสรุปยอดชำระสุทธิ |
| 5. ชำระเงิน | หน้าชำระเงิน (`/payment`) | สแกน QR Code พร้อมเพย์ หรือกรอกข้อมูลบัตร | ประมวลผลการชำระเงิน ตรวจสอบยอดเงิน และเปลี่ยนสถานะออเดอร์ |
| 6. รับ e-Ticket | หน้ารับตั๋ว (`/ticket-success`) | บันทึกรูป QR Code e-Ticket ลงในโทรศัพท์ | แสดงใบยืนยันการจอง e-Ticket พร้อม QR Code และปุ่มดาวน์โหลด/เซฟภาพ |

## การแมปกับโครงสร้างโปรเจกต์

| ขั้นตอน | หน้า Frontend | API หลักที่เรียกใช้ |
| --- | --- | --- |
| 1 | `frontend/pages/races.html` | `GET /api/races` |
| 2 | `frontend/pages/race-detail.html` | `GET /api/races/{id}` |
| 3 | `frontend/pages/select-zone.html` | `GET /api/races/{id}/zones`, `POST /api/bookings` |
| 4 | `frontend/pages/checkout.html` | `POST /api/bookings/{id}/checkout` |
| 5 | `frontend/pages/payment.html` | `POST /api/bookings/{id}/payment` |
| 6 | `frontend/pages/ticket-success.html` | `GET /api/bookings/{id}/ticket` |

## Edge Cases ที่ควรพัฒนาต่อในสัปดาห์ถัดไป

- โซนที่นั่งเต็มพอดีระหว่างผู้ใช้กำลังเลือกจำนวนตั๋ว (race condition ตอนล็อกที่นั่งจริงบน DB)
- ผู้ใช้ปิดหน้าเว็บระหว่างขั้นตอนชำระเงิน ต้องมีระบบปล่อยที่นั่งคืนอัตโนมัติเมื่อหมดเวลาล็อก (เช่น ล็อก 10-15 นาที)
- ชำระเงินสำเร็จแต่ระบบสร้าง booking ล้มเหลว (ต้องมี reconciliation/idempotency)
- กรอกเบอร์โทรผิดรูปแบบ หรือชื่อผู้ซื้อไม่ตรงกับผู้เข้าชมจริง
- ต้องการยกเลิก/ขอคืนเงินหลังจองสำเร็จ (ยังไม่ได้ทำในรอบนี้)

## Acceptance Criteria (สรุปจากเอกสารต้นทาง)

- ราคาที่แสดงในหน้าเลือกโซนต้องตรงกับยอดชำระจริงในหน้าชำระเงินเสมอ
- ระบบต้องล็อกที่นั่งชั่วคราวทันทีที่ผู้ใช้กดยืนยันเลือกโซน เพื่อป้องกันการจองซ้ำ
- ต้องแสดงสถานะที่นั่งคงเหลือแบบ real-time ในหน้าเลือกโซน
- หลังชำระเงินสำเร็จ ต้องออก e-Ticket พร้อม QR Code ทันที ดาวน์โหลด/บันทึกได้
